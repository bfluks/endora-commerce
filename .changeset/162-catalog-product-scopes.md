Product data scopes per sales channel and language.

- New error sentences in both bundles for `SCOPE_INVALID`, `SCOPE_INCOMPLETE`, `URL_KEY_TAKEN`, `URL_KEY_REDIRECT_TAKEOVER_REQUIRED` and `URL_REDIRECT_NOT_FOUND`, declared in the module's `errorCodes`.
- Migration `20261022T035133_catalog_product_scopes.ts` adds `product_channel_scopes` (per-channel status, publication window, audience, minimum order quantity and returnable flag; `NULL` inherits), `product_channel_language_scopes` (status per channel × language) and the global window `products.publish_from` / `products.publish_until`, with no backfill — with no rows, every product behaves as before. Both tables cascade on product hard delete and on sales channel delete. `CatalogProductRecord` now carries `publishFrom` / `publishUntil`.
- **New admin routes** `GET|PATCH /api/v1/admin/catalog/products/:id/scopes` (`catalog:read` / `catalog:write`): read and write a product's status, publication window, audience, minimum order quantity and returnable flag per sales channel, and its status per channel × language. `null` removes an override; a value for a channel the product is not in, or a language the channel does not offer, is refused with `422 SCOPE_INVALID` (removing an orphaned override is always allowed); a window that does not start before it ends with `422 VALIDATION_FAILED` (`details.field = 'window'`). Each write is the audited Command `product.scopes.update`, whose before-state re-sent through the same route restores it, and emits `product.updated.v1` with `changedFields` among `scopedStatus`, `publicationWindow`, `audience`, `orderRules`. An audience override naming organizations outside the channel is saved with an `audience_non_members` warning. Both answers name the organizations the audience rules name (`data.organizations`, read through `organizationDetailsPort`; an unreadable one is left out). These values are stored and audited; storefront reads do not apply them yet.
- **Behaviour change for API clients:** `PATCH /api/v1/admin/catalog/products/:id` accepts `publishFrom` / `publishUntil` (the global publication window; `422 VALIDATION_FAILED`, `details.field = 'window'`, when it does not start before it ends), and its `product.update` audit states carry both bounds.
