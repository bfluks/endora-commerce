## Standing rules for every task

1. **Rebuild what you edit.** Tests read each package's `dist`; `tsc` reads sources. After editing
   anything under `packages/`, run `pnpm --filter <package> run build` before a test that imports it
   (`@endora-commerce/contracts`, `@endora-commerce/mod-assets-library`, `@endora-commerce/admin-kit`).
   A test helper that imports a service from `src` can load a second copy of an entity class — import
   entities from `backend/test/helpers/package-entities.ts` as the existing assets suites do.
2. **Admin component tests render inside `<StrictMode>`** — wrap the element passed to
   `renderWithI18n` (`admin/test/helpers/render-with-i18n.tsx` does not add it). Set an "alive" flag in
   the effect body and clear it in cleanup; mark an action done only once its response has arrived.
3. **Never put a test next to a module's `src/manifest.ts`** — `manifests:check` rejects it. Module
   unit tests go under `src/backend/` beside their subject (the composition test beside
   `src/backend/index.ts`); admin tests under `admin/test/`; server-bound tests under
   `backend/test/{contract,integration}/`.
4. **Paths in `pnpm --filter backend …` commands resolve from `backend/`** — a module source is
   `../packages/modules/assets_library/src/…`. `check:*` scripts are `backend` scripts.
5. **Postgres-backed tests run one file per invocation**, from `backend/`, with the services
   environment **derived from the root `.env`, never hard-coded**: this repository is built on two
   machines whose published ports differ, and both record theirs in `.env` as `POSTGRES_PORT`,
   `REDIS_PORT`, `MEILISEARCH_PORT`. Nothing is exported — an agent's shell is reset between commands
   — so every server-bound command is written out in full in the **`[PG]` line form**:

   ```bash
   (cd backend && eval "$(grep -E '^(POSTGRES_PORT|POSTGRES_USER|POSTGRES_PASSWORD|POSTGRES_DB|REDIS_PORT|MEILISEARCH_PORT|MEILI_MASTER_KEY)=' ../.env)" && env TEST_DATABASE_URL="postgresql://${POSTGRES_USER:-b2b}:${POSTGRES_PASSWORD:-b2b}@localhost:${POSTGRES_PORT:-5432}/${POSTGRES_DB:-b2b}_test" REDIS_URL="redis://localhost:${REDIS_PORT:-6379}" MEILISEARCH_URL="http://localhost:${MEILISEARCH_PORT:-7700}" MEILISEARCH_API_KEY="${MEILI_MASTER_KEY:-devMasterKeyChangeMe}" pnpm exec vitest run <one file>)
   ```

   It reads only those seven keys, falls back to `.env.example`'s defaults for an absent key, and needs
   the root `.env` present — a fresh worktree has none until T000a copies it. To check the
   expansion on a new machine, run the line once with `sh -c 'echo $TEST_DATABASE_URL $REDIS_URL $MEILISEARCH_URL'`
   in place of `pnpm exec vitest run <one file>`. A module unit test needs no services:
   `pnpm --filter @endora-commerce/mod-assets-library exec vitest run <path under src/>`.
6. **Fixtures are per run.** Every asset a server-bound test creates gets a fresh id from the upload, a
   filename carrying `` `as156-${randomUUID().slice(0, 8)}` ``, and every permalink is
   `` `as156-${suffix}/…` ``; assertions check membership by id, never a list's length (the test
   database is shared). Forged rows use `randomUUID()` ids, never a constant. Assets a test creates are
   hard-deleted (row and file) in `afterAll`, with their `asset_object_cleanups` and
   `asset_permalink_releases` rows.
7. **No permanent shared-state mutation.** A test that changes a setting (`assets.local.base_dir`,
   `assets.soft_delete_retention_days`, `assets.max_file_size_mb`, `assets.allowed_file_types`,
   `assets.storage.adapter`, the S3 settings) reads the stored value first and writes it back in
   `afterAll`, then calls `adapters.invalidate()`. Sweeps are driven with an explicit `now` (the
   effective retention is at least one day — owner ruling P3 — so a zero setting cannot make a row due
   at once). Extra admins get **their own** stub session ids in `backend/test/helpers/test-actors.ts`
   (`ADMIN_COOKIES`) and their roles/users are created by the test file itself; no existing role is
   edited.
8. **A regenerated artefact is committed with its input** — `composer:generate` (migrations registry,
   module reference page, docs sidebar, module map), `manifests:generate` + `pnpm install --lockfile-only`
   (package manifests, lockfile), `UPDATE_OPENAPI_BASELINE=1` (OpenAPI fixture — added to the `env`
   list of the `[PG]` line of `test/contract/kernel/openapi-baseline.test.ts`, then the line run again
   without it).
9. **A new error code lands in one commit with all four of its places**: `ERROR_CODES`, the
   `MINTED_ERROR_CODES` ledger, the owning manifest's `errorCodes`, and the sentence in both bundles.
10. **Deleting or moving a file?** `grep -rn` its name across `backend/test`, `admin/test`, `docs/` and
    `backend/scripts/ledgers` in the same commit (`AGENTS.md`, traps). Ask what is **derived** from its
    location, not only what names it.
11. **Public repository**: English only in code, tests, specs, docs and commits (Polish only in
    `pl.json` and the Polish docs tree); no client names, ticket ids or private file references; neutral
    examples (`certificate.pdf`) per `specs/conventions/commercial-data.md`.
12. **Every deliberately changed existing assertion is named in its task** (research R-20). A red in an
    existing test that no task names is a defect, not something to update.
